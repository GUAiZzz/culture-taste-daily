# Public and private data boundaries

## Public repository may contain

- selected reader-facing content;
- source citations intended for publication;
- public issue manifests;
- issue-specific art-direction metadata;
- public QA reports and rendered previews;
- schemas and build code that contain no private instances;
- HarryTone repository, branch, and commit references.

## Public repository must not contain

- private source-ledger instances;
- rejected-candidate ledgers or internal scoring rationale;
- browsing logs, browser history, screenshots collected only for research, or local session data;
- private canonical HarryTone files or a snapshot of that repository;
- secrets, API tokens, credentials, cookies, private keys, `.env` files, or signing material;
- unlicensed third-party media;
- historical publication artifacts imported from the former site.

## Media rule

Credit is not permission. Any future publishable image requires a separately recorded usage-rights basis. Unknown rights must fail closed and the image must not enter the public artifact.

## Transfer rule

The private workspace may promote only the selected facts, publishable citations, approved content, and explicitly public metadata needed by an issue. It must never copy the private ledger itself.
